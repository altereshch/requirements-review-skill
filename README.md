# Requirements Review

Skill для Claude, який виконує структуроване рев'ю однієї або кількох вимог (requirement, user story, acceptance criteria) **перед** тест-аналізом — тобто до того, як за ними почнуть писати тест-кейси чи чек-листи.

Мета — знайти проблеми у формулюванні вимоги, а не переписати її за автора.

## Коли спрацьовує

Skill активується, коли користувач:
- просить перевірити вимогу / зробити рев'ю вимог;
- питає, чи готова вимога / user story / acceptance criteria до тестування або тест-аналізу;
- звертається без слова "рев'ю" — наприклад: *«глянь цю вимогу»*, *«чи все ок з цим формулюванням»*, *«перевір цей пункт з ТЗ»*.

## Що на виході

Для кожної вимоги — звіт із чотирьох частин, у такому порядку:

1. **Вердикт** — ✅ Готова до тест-аналізу / ⚠️ Потребує уточнень / ❌ Не готова
2. **Таблиця знахідок** — конкретні проблеми з точними цитатами, severity та пропозицією виправлення
3. **Питання до BA** — те, що неможливо виправити без відповіді власника вимоги
4. **Що добре** — 1–2 реальні сильні сторони формулювання

Якщо вимог декілька, окремо додається блок **«Перехресні знахідки»** — дублювання й конфлікти між вимогами.

## 7 критеріїв оцінки

| Критерій | Суть |
|---|---|
| Атомарність | Вимога описує рівно одну поведінку/правило |
| Однозначність | Немає слів на кшталт «швидко», «зручно», «коректно» без конкретного критерію |
| Повнота | Описані негативні сценарії та граничні значення, а не лише happy path |
| Несуперечність | Немає взаємовиключних тверджень у самій вимозі (і між вимогами, якщо їх декілька) |
| Неповторюваність | Вимога не дублює іншу надану вимогу |
| Тестованість | До кожного твердження можна сформулювати перевірку з очікуваним результатом |
| Реалізовність | Немає логічних протиріч чи взаємовиключних умов |

## Severity і вердикт

| Severity | Означає |
|---|---|
| **Critical** | Блокує тест-аналіз повністю — незрозуміло, що саме перевіряти |
| **Major** | Не блокує, але створює ризик пропущених сценаріїв або суперечливих тестів |
| **Minor** | Неточність без прямого ризику, можливі дрібні розбіжності у формулюванні |

Вердикт визначається автоматично за найвищим severity серед знахідок: Critical → ❌, Major (без Critical) → ⚠️, лише Minor або без знахідок → ✅.

## Ключові принципи (запобіжники)

Ці правила мають пріоритет над усім іншим у skill:

1. **Кожна знахідка — з точною дослівною цитатою.** Без цитати знахідка в звіт не потрапляє.
2. **Невпевненість → питання до BA, а не твердження про проблему.** Skill не додає знахідки "про всяк випадок".
3. **Жодних вигаданих деталей.** Якщо інформації для оцінки критерію бракує (наприклад, немає інших вимог для порівняння) — це прямо зазначається в звіті, а не додумується.

Перед видачею звіту skill проходить самоперевірку на 4 типові збої: галюцинації (вигадана цитата чи проблема), пропуски (незіставлені пари речень/вимог), хибний тон (завищений/занижений severity) та нестабільність вердиктів.

## Обмеження

- Пропозиція виправлення в таблиці — лише локальна (в межах рядка), повна альтернативна редакція вимоги пропонується тільки на окремий запит користувача.
- Критерій «Неповторюваність» перевіряється тільки якщо надано інші вимоги для порівняння.
- Skill оцінює лише те, що видно з тексту — не оцінює технічну складність реалізації.
